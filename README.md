# CareTrace — Diagnostic Odyssey Radar

**Topic:** Clinical Decision Making & Pattern Recognition in Health Care
**Author:** Pranali — MS Business Analytics & AI, University of Texas at Dallas
**Status:** Hackathon-stage proof of concept / decision-support prototype (not a clinical diagnostic tool)

## Problem

A single specialist referral, diagnostic test, or claim almost always looks
medically appropriate on its own. What's invisible to per-claim review is a
patient stuck in a **diagnostic odyssey** — bouncing between specialists,
accumulating diagnostic/imaging/lab claims, and never converging on a stable
diagnosis or a therapeutic claim. This POC detects that pattern directly
from claims sequences — no clinical notes, imaging, or genomic data required
— and routes flagged episodes to a human care coordinator for review.

## Product experience

CareTrace is designed as a **Healthcare Intelligence Control Center**, not a
generic analytics dashboard — a branded header with live AI/data status, a
demo-case picker for fast triage, an interactive clinical journey timeline
and referral graph, a "Pattern Reveal" panel that shows exactly why an
episode was flagged (signal-strength rated, click-to-expand evidence), a
live decision simulator (re-scores the episode in real time as you adjust a
feature), and four audience-specific views (Analyst / Executive / Technical
/ Responsible AI). Screenshots: `screenshots/analyst_view.png`,
`screenshots/executive_view.png`, `screenshots/technical_view.png`.

## What this demonstrates

- Episode reconstruction and clinically interpretable feature engineering
  from a raw claims stream (specialty fan-out, diagnostic-to-therapeutic
  ratio, diagnosis-code churn, visit-interval irregularity, referral
  "ping-pong" rate)
- An XGBoost classifier trained against an **independently simulated
  chart-audit label** (not derived from the same features the model sees —
  see *Data* below), with a held-out test set
- SHAP-based explainability at the individual-episode level
- K-Means clustering of at-risk episodes into named, interpretable
  **fragmentation typologies** (Specialist Fan-Out, Referral Ping-Pong,
  Diagnostic Loop)
- A separate **provider-level time-series drift check** — monthly z-score
  monitoring of each provider's own diagnostic-claim-share baseline
- A bounded, template-based **review-packet generator** ("agentic" layer)
  that assembles SHAP factors + typology + provider-drift context into a
  plain-language narrative for a care coordinator — never a new detection
  signal, never an autonomous action
- A Streamlit dashboard integrating all of the above with human-in-the-loop
  framing throughout

## Why conventional analytics misses this

Utilization review and risk-scoring tools evaluate claims or patients
independently, or via a single aggregate score. A referral "ping-pong"
pattern, a stalled diagnosis, or a rising diagnostic-to-therapeutic ratio
only becomes visible when claims are analyzed **as a connected sequence and
graph** — which per-encounter review and single-score models structurally
cannot see.

## Data

This repo ships **synthetic** claims data (`data/claims.csv`, generated by
`src/claims_generator.py`) with a schema loosely modeled on public CMS
claims structures (patient/episode ID, claim date, provider ID/specialty,
diagnosis code, claim type, allowed amount) — see `data/README.md` for full
transparency notes.

**Label design, stated explicitly:** the training label
(`confirmed_fragmentation`, in `data/chart_audit_outcomes.csv`) is generated
by a *separate* simulated chart-audit process — driven by the same latent
"care complexity" that shapes the visible claims pattern, but with
independent audit noise and an unobserved "chart context" signal never
joined into the feature table. This mirrors how a real label would arise
(a case manager's retrospective chart review), and specifically avoids the
classic trap of deriving a label as a deterministic function of the exact
features the model is trained on — an earlier draft of this generator did
that by accident and produced a suspicious 1.0 AUC; see
`quality_control_review.md` for how it was caught and fixed.

**To adapt to real data:** point `src/claims_generator.py`'s output at a
de-identified claims extract with equivalent columns, and replace the
simulated chart-audit file with real case-manager-confirmed outcomes joined
by episode ID. No other pipeline code changes required.

## Run it locally

```bash
pip install -r requirements.txt
python -m src.pipeline        # generates data, trains model, scores all episodes
streamlit run app.py          # launch the dashboard
```

## Validation

On a held-out test set (25% split, stratified): **ROC-AUC 0.899**, **PR-AUC
0.502**, precision 0.52 / recall 0.61 at a 0.5 probability threshold
(9.3% positive rate). Metrics reflect the synthetic, generated dataset
described above and are illustrative of the *pipeline*, not a claim about
production performance on real claims data.

## Responsible AI

This prototype is a **decision-support tool**, not an autonomous clinical
decision-maker or diagnostic device. It has not been clinically validated
and has not been evaluated for subgroup performance disparities. Every
output — the classifier probability, the typology, the provider-drift
context, and the review packet — is scoped as a recommendation for *human
review* by a care coordinator, never an automated action. See the full
report (`report/CareTrace_Report.docx`) for the complete responsible-AI
framework covering bias, drift, calibration, and monitoring, and see
`src/review_packet.py`'s docstring for the explicit boundary between
deterministic detection and the bounded agentic layer.

## Future enhancements

- Validate against real, de-identified claims data and real case-manager
  chart-review outcomes under appropriate governance
- Subgroup fairness audit (age, geography, payer type, complaint frequency)
- Swap the template-based review-packet composer for an LLM API call over
  the same structured signals (interface already isolated in
  `src/review_packet.py`)
- Calibration monitoring and periodic retraining as care patterns and
  coding practices shift
- Extend provider drift beyond diagnostic-claim share to referral-network
  centrality changes
